Licao 01 / 7 minutos

Um flow profissional comeca por um contrato.

Antes de conectar API, banco ou planilha, defina o que entra, o que acontece e qual evidencia sai. Esse pequeno habito evita automacoes dificeis de reutilizar e vender.

Vitoria: criar e executar um flow parametrizado Nivel: primeiro contato

Em Kestra, um flow e uma declaracao versionavel de um processo. A primeira versao nao precisa ser grande; ela precisa tornar o contrato visivel.

Entrada

O dado que muda entre execucoes, como cliente, periodo ou referencia.

Tarefa

Um passo executavel que registra, consulta, transforma ou envia algo.

Saida

O resultado que outra tarefa, outro flow ou uma pessoa consegue verificar.

Se um cliente pedir a mesma automacao para outra empresa, o que deve mudar: o flow ou os inputs?

O flow da nossa primeira entrega

Este exemplo confirma uma solicitacao de onboarding. Ele e deliberadamente pequeno: dois inputs, duas tarefas e uma saida declarada.

onboarding_confirmation.yaml 
id: onboarding_confirmation
namespace: training.kestra
description: Confirma uma solicitacao de onboarding

inputs:
  - id: customer
    type: STRING
    defaults: Acme
  - id: request_id
    type: STRING
    defaults: demo-001

tasks:
  - id: announce
    type: io.kestra.plugin.core.log.Log
    message: "Iniciando {{ inputs.customer }} / {{ inputs.request_id }}"

  - id: result
    type: io.kestra.plugin.core.debug.Return
    format: "ready: {{ inputs.customer }} / {{ inputs.request_id }}"

outputs:
  - id: status
    type: STRING
    value: "{{ outputs.result.value }}"

Repare na separacao: customer e request_id sao dados da execucao; announce deixa um rastro no log; status e um resultado que pode ser consumido depois.

Execute e observe

Se voce tiver Kestra Cloud ou uma instancia local, cole o YAML no editor de flows. Se ainda nao tiver ambiente, leia o fluxo como um contrato e use o quiz abaixo; a instalacao entra depois, quando a forma do processo estiver clara.

Crie o flow

Use o YAML acima e mantenha o namespace de treinamento por enquanto.

Execute com dados diferentes

Troque customer e request_id para simular dois clientes sem editar a definicao.

Confira as duas evidencias

No log, procure a mensagem de announce; na aba de input/output, confira status.

Uma decisao de produto

Quando voce vender uma automacao, o cliente nao compra YAML. Ele compra um resultado repetivel. Para cada flow, escreva uma frase de saida que possa ser verificada por alguem que nao participou da implementacao.

O que guardar

  • Inputs variam por execucao.
  • Tasks produzem efeitos.
  • Outputs tornam o resultado verificavel.

Alerta profissional

Outputs ficam armazenados no backend. Nunca use outputs para transportar senhas, tokens ou outras informacoes sensiveis.
